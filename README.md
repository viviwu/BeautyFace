# BeautyFace

面向 **macOS（Apple Silicon / arm64）与 iOS** 的人像（面部为主）照片美化 App，同时提供 Swift Package 形式的 SDK。第一版专注于**静态图片**，以头部与面部处理为主，支持多人脸。身体部分只做颈部与肩部的协调，保证脸与躯体过渡自然。

- 状态：**M0–M8 已完成（Mac）**，M9 阶段性完成；M8.1「小头联动」与 iPhone 真机验证、M10 验收按约定后置（见 [dev_ledger.md](dev_ledger.md)）
- 最后更新：2026-11-06
- 开发台账（ADR、里程碑、计划）：见 [dev_ledger.md](dev_ledger.md)

## 一、目标与范围

### 1.1 第一版（v1）做什么

- 平台：macOS 15+（Apple Silicon / arm64）、iOS 18+
- 输入：静态图片（相册、拍照、文件），HEIC / JPEG / PNG
- 处理：皮肤美化、五官与脸型形变、程序化美妆、颈肩协调
- 多人脸：逐张检测，各自独立参数
- 输出：处理后的图片，长边 ≤ 4096 像素，保留 EXIF 与颜色配置
- 交付：Swift Package 形式的 SDK、SwiftUI App（macOS / iOS），以及开发调试命令行工具 AutoBeauty
- 调试：核心功能开发阶段由 AutoBeauty 直接读取 `SampleImages/` 批处理，无需相册交互与人工点击

### 1.2 第一版明确不做

- 视频处理与实时相机预览
- 精细的身体塑形（瘦身、瘦腰、瘦腿、长腿、增高等）
- 全分辨率输出（4800 万像素原图按 4096 长边处理与输出）
- 基于美术素材的美妆（美妆全部程序化生成）
- Android 版本（算法层保持可移植，Android 在后续版本）
- 商用发布（暂不考虑，但依赖选型尽量避开许可风险）

### 1.3 运行与兼容

- 部署目标：iOS 18、macOS 15（Apple Silicon / arm64）
- 支持平台：macOS（arm64）、iOS
- 验收机型：iPhone 17（A19）、iPhone Air（A19 Pro），均运行 iOS 26；真机验证推迟到核心功能基本完成后
- 系统相册（PhotosPicker）路径只在非 Debug 模式下验证
- Debug 处理结果由 AutoBeauty 写入仓库 `processed/`；Release / iOS 由用户选择保存或导出
- 所有处理在设备端完成，不联网

## 三、架构

```
┌──────────────────────────────────────────────┐
│ BeautyFaceDemo（SwiftUI）                       │
│ 选图 · 参数面板 · 预设 · 对比 · 导出              │
├──────────────────────────────────────────────┤
│ BFKit（依赖 Apple 框架）                         │
│ Core：解码、EXIF、纹理转换、编码                  │
│ Vision：人脸、关键点、人像蒙版（姿态 B 级预留）     │
│ Render：Metal 管线与内核                         │
│ Pipeline：阶段编排、缓存、预览/导出                │
├──────────────────────────────────────────────┤
│ BFAlgorithms（纯 Swift，无平台依赖）               │
│ Geometry：MLS 求解、位移场、控制点映射              │
│ Params：参数模型、强度映射、预设                   │
│ Makeup：程序化妆面参数                            │
│ Body：颈肩衰减 + 人像蒙版约束（M8）                │
└──────────────────────────────────────────────┘
```

**依赖方向**：BeautyFaceDemo / AutoBeauty → BFKit → BFAlgorithms。`BFAlgorithms` 不能反向依赖任何上层模块，也不能 `import` Apple 框架。

> 早期架构图里的「人体姿态」是 B 级预留：M8 只用 76 点关键点 + Vision 人像蒙版推断颈根与肩线，**不引入** `VNDetectHumanBodyPoseRequest`（见 3.10）。`BFKit/Shaders/` 目录也不存在，所有 MSL 内核以字符串内联在 Swift 渲染器里。

### 3.1 处理流水线

```
原图解码（缩放到 4096 长边）→ rgba16Float 工作纹理
  → 检测：人脸框、76 点关键点、人像蒙版
  → 颜色与平滑：美白、磨皮、亮眼、白牙、去黑眼圈、去痘印（不改几何）
  → 几何：合并位移场（脸部形变 + 颈肩协调，受 76 点与分割蒙版约束） → 单次 warp
  → 变换关键点（同一 MLS 映射）
  → 美妆：使用变形后的关键点定位
  → 输出：编码保存，保留 EXIF 与颜色配置；Debug 由 AutoBeauty 写入 processed/，Release / iOS 由用户导出
```

### 3.2 对外 API

`BeautyEngine` 把「检测与蒙版」和「渲染」拆成两步，让交互式调参不需要反复跑 Vision：

```swift
let engine = try BeautyEngine()
let decoded = try ImageDecoder.decode(data: data, maxLongEdge: BeautyQuality.preview.maxLongEdge)
let analysis = try engine.analyze(decoded: decoded, quality: .preview)  // 检测 + 皮肤/局部蒙版，可缓存
let preview = try engine.render(analysis: analysis, parameters: params) // 只重算颜色与形变
let final   = try engine.render(analysis: fullAnalysis, parameters: params)

// 一次性处理（AutoBeauty / SDK 调用方）仍可用兼容入口：
let result = try engine.process(decoded: decoded, parameters: params, quality: .full)
```

`BeautyAnalysis` 持有 `DecodedImage`、`DetectionResult`、`SkinMask`、`RetouchMask` 与质量档位；`BeautyResult` 返回 `CGImage` 与 `ImageMetadata`。`process(...)` 现在是 `analyze` + `render` 的组合，行为与 M6 完全一致。

### 3.3 性能与交互策略

- 检测结果与蒙版按图片缓存，调节参数时不重新检测
- 拖动滑杆时使用 1024 像素的预览代理图，松手或导出时使用 4096 工作图
- 形变只重算 MLS 与位移场，属于小规模 CPU 计算
- `BeautyFaceDemo` 的实现：所有耗时工作串行在一条 `DispatchQueue` 上；滑杆变化做 50 ms 防抖；用递增的 generation token 丢弃过期回传，避免换图时旧画面覆盖新照片；导出时按 `.full` 重新分析一次（蒙版分辨率与像素坐标随质量档位变化），再编码为 PNG

### 3.4 局部修饰（M4）

蒙版在皮肤蒙版分辨率（预览 256 / 全分辨率 512）上生成，渲染时按双线性采样放大，因此边缘天然柔和。

| 区域 | 定位方式 | 判据 | 渲染 |
|---|---|---|---|
| 眼白 | 眼轮廓多边形（76 点） | 绝对亮度 + 「相对眼内中位亮度」取较大者，并要求低饱和 | 提亮并轻微去饱和，虹膜不参与 |
| 牙齿 | 内唇多边形（缺失时退回外唇） | 亮度高、饱和度低、无红偏 | 提亮 + 轻微提升蓝通道（中和偏黄） |
| 眼下 | 眼睛下缘外推的椭圆 | 皮肤蒙版内、亮度低于全脸平均 | 加性提亮 + 轻微微暖中和，避免橙色条带 |
| 痘印 | 皮肤蒙版（无需额外通道） | 低频底色与原始像素的亮度差 | 按比例抬升像素自身亮度，并向邻域色度收敛 |

眼白使用「绝对 + 相对」双判据的原因：实测暗光、眯眼、小尺寸素材中眼内最高亮度只有 0.35~0.55，纯绝对阈值会完全失效；而纯相对判据在眼白占据多边形大部分时会自我抵消。闭眼时眼内亮度分布平坦，两个判据都不成立，蒙版自然为空。

去痘印的参考亮度取自原图的低频模糊（不取已磨皮 / 已美白的像素），因此美白、提亮不会抵消瑕疵检测；修复采用增益方式抬升像素自身纹理，而不是替换成模糊值。

### 3.5 皮肤蒙版判据

肤色判定有两种模式，按是否检测到人脸切换：

| 模式 | 触发条件 | 判据 |
|---|---|---|
| 相对（首选） | 检测到人脸 | 从人脸框内采样肤色参考，按「亮度归一化色度距离」判定 |
| 绝对（兜底） | 无人脸 / 采样不足 | 固定 YCbCr 阈值带 + 亮度与饱和度下限 |

相对判据的核心是把色度按亮度归一化：`((Cb - 0.5) / luma, (Cr - 0.5) / luma)`。漫反射光照下 RGB 同比缩放，Cb/Cr 与 luma 同比变化，因此该比值对阴影与高光不敏感，只在肤色真正改变时才移动。

这样做的原因是绝对阈值无法区分「暖白色衣物」与「偏暖肤色」——实测一张室内自拍里，面部肤色 Cb/Cr 为 (0.41, 0.65)、白 T 恤为 (0.43, 0.57)，两者都落在传统肤色带内，饱和度 0.36 与 0.22 也没有清晰分界。改用相对判据后，衣物到肤色参考的归一化色度距离为 0.19，而同一张脸上的肤色像素集中在 0.01~0.03，可以稳定区分。

参考值取人脸框内缩 12%、排除眼/唇/眉之后所有像素的中位数，对头发丝、鼻孔、痣等离群点稳健；单张人脸采样不足 40 像素时退回绝对判据。

判定阈值随 `tolerance` 缩放：内半径 `0.05 + 0.02 × tolerance`，外半径 `0.09 + 0.04 × tolerance`，两者之间用 smoothstep 平滑过渡。

在该照片上的实测效果：白 T 恤亮度变化从 +9.74 降到 +0.11（变化像素 99.9% → 1.35%，领口缝线纹理保留），脸部仍为 +7.00、脖子 +8.44，背景严格 0；皮肤蒙版覆盖率 61.2% → 25.8%。

已知限制：混合肤色的合影共用同一参考；强单色光会让参考整体偏移；鼻梁镜面高光与面部绒毛被白光稀释后落在蒙版外，在磨皮强度拉满时会凸显为亮丝（默认档位不可见）。

### 3.6 磨皮：亮度引导的保边滤波

磨皮不使用高斯模糊，而是**以原图亮度为引导图的保边滤波**（guided filter）。对每个像素在局部窗口内拟合线性模型 `q = a·I + b`，`I` 为引导图（原图亮度），`a`、`b` 由窗口内的均值与协方差解出：

- **平坦的皮肤区域**：局部方差远小于正则项 `eps`，`a → 0`，输出趋近窗口均值，毛孔与细纹被抹平；
- **强边缘**（眉毛、睫毛、发丝、眼白与眼睑交界、唇线）：局部方差远大于 `eps`，`a → 1`，输出趋近原图，边缘完整保留。

因此强度拉满时皮肤被磨平，而五官轮廓与毛发不变淡、不变形——不会出现高斯磨皮那种「整张脸一起糊掉」的结果。

| 参数 | 取值 |
|---|---|
| 窗口半径 | `max(1, scale × (3 + 9 × smoothing))`，`scale = max(1, 长边 / 1024)` |
| 正则项 eps | `0.010 + 0.040 × smoothing`；半平滑点落在亮度标准差 ≈ √eps 处 |
| 混合权重 | `0.85 × smoothing × 皮肤蒙版` |

实现采用 Fast Guided Filter：统计量与线性系数在 1/4 分辨率上计算（4×4 方框降采样 + 两次 `MPSImageBox`），再按全分辨率双线性放大后回代。开销约为全分辨率的 1/16，实测在 2316×3088 样图上与不做磨皮相比没有可测差异，并省掉了原先那张全分辨率高斯纹理。

去痘印的低频参考仍然用高斯：那里要的是「把瑕疵平均掉」的大尺度均值，保边反而会把瑕疵本身留下来。

### 3.7 脸型形变（M5）

脸型（小脸 / 瘦脸 / 窄脸 / V 脸 / 下巴 / 额头 / 颧骨）用 **MLS 形变**（Schaefer et al. 2006，纯 Swift 实现于 BFAlgorithms，无平台依赖）：

- **求解**：逆向映射 `f(v)` 输出「输出像素 → 源图采样位置」。控制点上精确成立（`f(p_i) = q_i`），远离控制点时按 `1/(d²+ε)` 权重衰减回恒等。
- **控制点**：76 点轮廓按纵坐标分带位移（下颌、V 脸、下巴、额头、颧骨各占不同区段），单点位移上限为脸高的 10%、超出线性压缩（R-02）；图像边框加恒等锚点。
- **位移场**：多张脸的控制点合入一次 MLS，在长边 128 节点的粗网格上预计算位移。网格节点显式乘距离衰减——`0.15×R` 以内不衰减、`0.45×R` 以外**严格为 0**（R 为脸半径），保证背景零形变；发丝随脸小幅移动属设计内的混合带。
- **折叠防护（R-02）**：对位移场做中心差分雅可比，行列式 ≤ 0（重采样会撕裂）即按 0.7 整体回退强度重解。实测全参数拉满最小雅可比 0.042 > 0。
- **渲染**：位移场上传为 `rgba16Float` 纹理，Metal kernel 双线性采样位移后对源图双线性重采样——**整图只重采样一次**（ADR-006）；位移可忽略时直接返回原图。
- **顺序**：颜色与平滑之后、编码之前做 warp（ADR-007）；位移场同时供后续美妆阶段变换关键点，保证形变与美妆不错位。

| 参数 | 取值 |
|---|---|
| 网格 | 长边 128 节点，多脸合入一次求解 |
| 位移上限 | 脸高的 10%，超出线性压缩 |
| 距离衰减 | smoothstep(0.45R, 0.15R, 到最近关键点的距离) |
| 折叠回退 | ×0.7 重解，最多 12 次 |

实测（`IMG_0789.HEIC`）：全参数拉满最大位移 122px、无折叠、背景与衣服逐像素不变；warp 自身开销 < 0.3s。

收窄模型已从「按 t 区段钟形叠加」改为**单调 C1 宽度锥形**：所有收窄参数线性合成一个总量，乘一条从太阳穴到下巴单调递增的锥形函数，逐点按自身横向距离等比压缩——宽度剖面由构造保证单调，两侧波浪与腮部外鼓在数学上不可能出现。

### 3.8 五官形变（M6）

五官（大眼 / 眼距 / 眉间距 / 眉毛粗细 / 鼻翼 / 嘴型）与脸型**共用一次 warp**，但拆成**两个独立 MLS 场再叠加**：

- **场 A（脸型）**：轮廓带位移（单调 C1 宽度锥形）、五官零位移锚定；
- **场 B（五官）**：五官带位移、**轮廓沿弧长加密锚定为零**（每段 8 等分）。

合入同一个场时，五官大位移会把脸缘拽出波浪；拆分后五官形变在 MLS 插值下到不了轮廓，**边缘 = 纯锥形剖面，与五官强度无关**。两场叠加后仍只做一次 warp，折叠检查对总场统一生效。

| 参数 | 驱动方式 | 系数（p=1 时） |
|---|---|---|
| 大眼 | 眼眶点绕眼睛质心径向外移，纵向 0.60、横向 0.30（横向刻意压低：外眼角外推会推挤脸缘） | 眼裂高度 +60% |
| 眼距 | 单侧整眼（含瞳孔）同一水平平移，眼形不变，位移相对瞳距归一 | ±15% 瞳距 |
| 眉间距 | 双眉整体向眉心平移，眉形不变 | ±15% 眉距 |
| 眉毛粗细 | 眉形折线绕自身质心纵向拉伸（0.45），MLS 把眉部暗色带拉宽 | 属近似（R-16） |
| 鼻翼 | 鼻部点向鼻中轴按横向距离等比收拢（0.32） | |
| 嘴型 | 嘴角按横向距离平方加权上扬（0.30）为主，水平收拢（0.08）只是点缀——收太多会与脸型收窄叠加导致比例失调 | |

轮廓控制点同时在场 A 沿弧长 3 倍加密（位移线性插值），边缘被密集钉在锥形剖面上。五官点位移与脸型共用位移上限（脸高的 10%，R-02）；参数全为零时五官控制点退化为零位移锚点。

实测（`IMG_0789.HEIC`，脸型 0.5/0.6/0.5 + 六项五官）：最大位移 93px、最小雅可比 0.201（无折叠）、背景逐像素不变；边缘收窄比例沿太阳穴 → 下巴**严格单调**（`--dump-edge` 探针沿轮廓折线加密采样验证，脸侧反向点 0 个）。

---

### 3.9 程序化美妆（M7）

口红 / 腮红 / 眉毛加深 / 眼影四路美妆**不依赖美术素材**，由形变后的关键点程序化生成（ADR-007 / ADR-008）：

- **蒙版生成**（`MakeupMaskGenerator`，BFKit）：用 **warp 之后的** `FaceGeometry` 关键点生成四路 0...1 蒙版（长边 512 + 盒滤波羽化）——
  - 口红：外唇多边形栅格化**减去口内**（`FaceGeometry.innerLips`，口内不上色也不参与 MLS）；
  - 腮红：眼心到唇心连线的颊部椭圆软边；
  - 眉毛：沿眉形折线撒圆盘补厚度（Vision 眉毛无厚度轮廓）；
  - 眼影：上眼睑点向上偏移的眼睑带。
- **合成**（`MakeupRenderer`，Metal）：在 warp **之后**单 pass 合成——口红用**色度替换、亮度保持**（唇纹与明暗完整保留，实测唇色 (95,25,29) → (134,0,16) 红分量 +39、亮度基本不变）；腮红 / 眼影低权重叠色；眉毛向深色混合。
- **参数**（`MakeupParameters`，BFAlgorithms）：四项强度各配**可自定义颜色**（gamma 空间 RGB），预设只保存参数不保存素材；管线顺序为 颜色 → warp → 美妆 → 编码。

实测：全流程组合渲染 2223 ms（Mac debug，含形变与美妆）；背景逐像素不变；蒙版随脸型 / 五官形变对齐（形变后关键点驱动）。AutoBeauty 新增 `--lipstick / --blush / --brow / --shadow`。

### 3.10 颈肩协调（M8）

M5 的位移场按「到最近脸部关键点的距离」各向同性衰减（`0.15×R` 内不衰减、`0.45×R` 外严格为 0），这保证了背景零形变，但也意味着**脸被收窄时脖子不动**——脸与颈的交界可能出现断层（R-07）。M8 不改变 M5 的脸部位移，而是把它的影响沿颈部向下平滑延伸到肩线。

**做法**（完整公式与设计取舍见 `dev_ledger.md` 3.12）：

- **有向颈部走廊**：只在下巴以下、以颈部中轴为中心的窄区域内补一段衰减权重（肩线处为 0、颈根处为 1，横向软羽化），而不是把 M5 的径向衰减圈调大——后者会让位移向左右与上方扩散，重新造成背景形变。
- **人像蒙版约束（实测后定稿）**：最终权重 = `max(原径向衰减, 颈部走廊 × 人像蒙版门)`。门控**只作用于新增的颈部走廊**，不碰原有径向衰减——这保证脸部内位移与 M8 之前逐像素一致，同时走廊在人像蒙版外严格为 0。设计稿原本是 `max(radial, neck) × gate`，在头部特写 `IMG_0789` 上因分割蒙版在脸缘内缩而把脸部形变砍半（强度 1.00 → 0.49），按「效果优先」原则改为现式。Vision 分割接近硬二值，门控采样带 3×3 邻域羽化以消除权重阶跃、避免雅可比折叠。
- **肩线从蒙版推断**：沿 y 扫描人像蒙版宽度，颈段窄、肩线处突然展宽即为肩线；估计失败时用固定比例兜底。**不引入人体姿态检测**（B 级预留）。
- **一次 warp 不变**：权重表只在 `DisplacementField.solve` 里算一次，与脸型 / 五官位移合并后仍只做一次重采样（ADR-006），不新增 Metal 内核、纹理或用户参数。美妆继续用同一位移场变换关键点。
- **跨层保持纯 Swift**：Vision 的 `SegmentationMask` 在 BFKit 侧转换为纯 Swift 的 `PersonMaskGrid`（归一化双线性采样）再传入算法层（ADR-005）；蒙版缺失时自动退回 M5 原有行为，也可用 `bodyCoordination = false` 一键回退。

**效果优先**：以上权重是起点不是教条。验收以 `SampleImages/IMG_0291.jpg`（完整肩线、灰蓝衬衫 + 白 T 恤、暖色复杂背景）与 `IMG_0789.HEIC`（M5 基线：白 T 恤 + 纯灰墙，肩被裁在底边、走兜底路径）的前后目视对比为准——数值判据全绿不等于通过，要看起来**下巴→颈→肩连续、无硬边、背景与衣物纹丝不动**。AutoBeauty 的 `--no-body` A/B 开关、`--dump-neck` 颈部剖面探针与 `_body.png` 权重热图用于调参（见第六节）。

**范围说明**：ADR-009 把「小头」标为 B 级，已从 M8 拆为 M8.1（台账 Q-05）；M8 只交付 A 级的颈肩过渡，不做精细身体塑形。

**实现状态（2026-11-06）**：双素材数值验收通过——`IMG_0291` 走蒙版宽度突变主方案、`IMG_0789` 走固定比例兜底，两条路径都覆盖；M8 最大新增权重 0.939 / 0.867，蒙版外新增权重 `0.000000`、肩线以下最大位移 `0.0000 px`，最小雅可比 0.562 / 0.368 > 0、强度均 1.00，脸部与 M5 基线逐像素一致。A/B 目视中差异只落在下巴→颈→领口一条连续弧线，无硬边，灰墙与白 T 恤基本不变。目视对比图见 `processed/m8/`。

**顺带修复的既有 bug**：真实半身像上发现脸型形变落到了胸口而非脸上——`DisplacementField` 网格 row 0 是 y 向上 y=0（图像下沿），而 Metal 纹理 row 0 是图像上沿，位移纹理上传时少了一次翻转（源图走 `CGContext.draw` 自带翻转，因此一直没暴露）。`WarpRenderer.makeDisplacementTexture` 现在按行倒序上传并把 `dy` 取反，差异质心 0.680 → 0.305。旧单测用上下近似对称的居中合成脸，故未能发现；已补方向回归测试。此修复也是 M8 颈部走廊能落在正确位置的前提。

**环境要求**

- macOS 15 或更新版本，Apple Silicon 芯片（日常开发与调试在此运行）
- iPhone 17 或 iPhone Air 真机（最终验收；Mac 上的性能与内存数据不作为验收依据，见 ADR-013 / ADR-014）

**默认示例照片**

真实人像不入库。首次运行前在本地生成一次：

**App 界面**

- 顶部工具栏：预设（原图 / 自然 / 精致 / 自定义）、照片图库、打开文件、恢复默认、导出 PNG
- 左侧竖直功能栏：**6 类**——美肤 / 局部修饰 / 脸型 / 五官 / **美妆** / 预设，切换后底部出现对应控件

## 七、测试

- **算法层**：`swift test` 在 Mac 上运行，覆盖 MLS 求解、参数映射、预设编解码、衰减函数。
- **AutoBeauty**：批量处理 `SampleImages/`，输出到 `processed/` 做回归与前后对比。
- **恒等回归**：合成测试图经 `rgba16Float` 工作纹理往返，最大通道误差 ≤ 1 灰阶。
- **人脸检测**：样例图检测 1 张脸、拼接图检测 2 张脸；76 点关键点；人像蒙版非空。
- **皮肤处理**：肤色 + 人像蒙版生成皮肤蒙版，眼/唇多边形排除；恒等参数往返误差 ≤ 1 灰阶。
- **皮肤蒙版判据**：暖白色衣物（Cb/Cr 落在传统肤色带内）不应算作皮肤；同一肤色压暗 40% 后仍应被识别，用于验证亮度归一化对阴影不敏感。
- **局部修饰**：合成人像（眼白/虹膜/牙齿/唇/眼下暗沉）验证蒙版几何——眼白覆盖巩膜且不含虹膜，牙齿不含唇，眼下落在眼睛下方，背景与额头为 0。
- **痘印修复**：合成暗斑经去痘印后亮度回升，无瑕疵区域不变；开启美白后相对修复量不被抵消。
- **局部渲染隔离**：亮眼 / 白牙 / 去黑眼圈各自只改变对应蒙版内像素，蒙版外 ≤ 1 灰阶。
- **快照测试**：固定图片与参数，输出与参考图比较，允许少量容差。
- **背景保护**：蒙版外像素变化接近 0（实测 ≤ 1 灰阶）。
- **几何检查**：位移场雅可比行列式为正，防止折叠；极端位移触发强度回退后仍为正。
- **MLS 求解器**：恒等控制点返回原值、控制点上精确命中、远场衰减回恒等、多脸互不干扰。
- **脸型参数**：7 项参数各自只朝预期方向移动对应的轮廓带，其余带不受影响；位移超上限被线性压缩。
- **Warp 渲染**：零位移返回原图；恒等误差 ≤ 1 灰阶；强形变下背景与衣服不变；`testDisplacementFieldMapsYUpToRasterRows` 锁定 y 向上位移场 → 光栅行序的换算方向，防止形变垂直镜像复发。
- **M8 颈肩**：`PersonMaskGrid` y 向上采样、上/下不对称合成蒙版的方向锁定、`Config` 属性默认值与显式 `init` 一致性、`--shoulder-line` 覆盖生效；`bodyCoordination = false` 逐位回到 M5 基线；肩线以下与人像蒙版外的 M8 新增权重严格 0；美妆仍用同一总场变换关键点。
- **App 源码**：本机 `xcodebuild` 受嵌套沙箱限制无法解析本地包，改用 SwiftPM harness 把 6 个源文件作为 target 全量编译（含 SwiftUI / `@Observable` / PhotosUI）。
- **真机验收**：两台设备 × 三类素材（前置自拍、4800 万像素原图、多人合影）——按约定后置。

一键跑齐上述自动检查：`bash scripts/verify.sh`（ADR-005 守护 + BFAlgorithms 50 项 + BFKit 51 项 + AutoBeauty 构建 + App 源码类型检查）。

详细的验收标准与测量方法见 `dev_ledger.md` 的里程碑章节。

## 九、隐私

- 图片与处理结果只保存在设备本地。
