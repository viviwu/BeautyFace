# BeautyFace

面向 **macOS（Apple Silicon / arm64）与 iOS** 的人像（面部为主）照片美化 App，同时提供 Swift Package 形式的 SDK。第一版专注于**静态图片**，以头部与面部处理为主，支持多人脸。身体部分只做颈部与肩部的协调，保证脸与躯体过渡自然。

- 状态：M5 完成（脸型形变：MLS 求解器、粗网格位移场、单次 warp），准备进入 M6（五官形变）
- 最后更新：2026-11-04
- 开发台账（ADR、里程碑、计划）：见 [dev_ledger.md](dev_ledger.md)

## 一、目标与范围

### 1.1 第一版（v1）做什么

- 平台：macOS 15+（Apple Silicon / arm64）、iOS 18+
- 输入：静态图片（相册、拍照、文件），HEIC / JPEG / PNG
- 处理：皮肤美化、五官与脸型形变、程序化美妆、颈肩协调
- 多人脸：逐张检测，各自独立参数
- 输出：处理后的图片，长边 ≤ 4096 像素，保留 EXIF 与颜色配置
- 交付：Swift Package 形式的 SDK、SwiftUI App（macOS / iOS），以及开发调试命令行工具 AutoBeauty
- 调试：核心功能开发阶段由 AutoBeauty 直接读取 `SampleImages/` 批处理，无需相册交互与人工点击

### 1.2 第一版明确不做

- 视频处理与实时相机预览
- 精细的身体塑形（瘦身、瘦腰、瘦腿、长腿、增高等）
- 全分辨率输出（4800 万像素原图按 4096 长边处理与输出）
- 基于美术素材的美妆（美妆全部程序化生成）
- Android 版本（算法层保持可移植，Android 在后续版本）
- 商用发布（暂不考虑，但依赖选型尽量避开许可风险）

### 1.3 运行与兼容

- 部署目标：iOS 18、macOS 15（Apple Silicon / arm64）
- 支持平台：macOS（arm64）、iOS
- 验收机型：iPhone 17（A19）、iPhone Air（A19 Pro），均运行 iOS 26；真机验证推迟到核心功能基本完成后
- 系统相册（PhotosPicker）路径只在非 Debug 模式下验证
- Debug 处理结果由 AutoBeauty 写入仓库 `processed/`；Release / iOS 由用户选择保存或导出
- 所有处理在设备端完成，不联网

## 二、功能清单

分级含义：**A** 第一版必须完成；**B** A 完成后补充，效果可能偏粗；**C** 本版不做。

| 多人脸 | A | 逐张检测，各自独立参数 |

### 基础美颜

| 功能 | 级别 | 说明 |

| 增亮 / 提亮 | A | 面部整体亮度与对比度调整，保留高光 |

| 去黑眼圈 | A | 眼下区域提亮并校正偏色 |

## 三、架构

```
┌──────────────────────────────────────────────┐
│ BeautyFaceDemo（SwiftUI）                       │
│ 选图 · 参数面板 · 预设 · 对比 · 导出              │
├──────────────────────────────────────────────┤
│ BFKit（依赖 Apple 框架）                         │
│ Core：解码、EXIF、纹理转换、编码                  │
│ Vision：人脸、关键点、人像蒙版、人体姿态            │
│ Render：Metal 管线与内核                         │
│ Pipeline：阶段编排、缓存、预览/导出                │
├──────────────────────────────────────────────┤
│ BFAlgorithms（纯 Swift，无平台依赖）               │
│ Geometry：MLS 求解、位移场、控制点映射              │
│ Params：参数模型、强度映射、预设                   │
│ Makeup：程序化妆面参数                            │
│ Body：颈肩衰减函数                                │
└──────────────────────────────────────────────┘
```

**依赖方向**：BeautyFaceDemo / AutoBeauty → BFKit → BFAlgorithms。`BFAlgorithms` 不能反向依赖任何上层模块，也不能 `import` Apple 框架。

### 3.1 处理流水线

```
原图解码（缩放到 4096 长边）→ rgba16Float 工作纹理
  → 检测：人脸框、76 点关键点、人像蒙版、人体姿态
  → 颜色与平滑：美白、磨皮、亮眼、白牙、去黑眼圈、去痘印（不改几何）
  → 几何：合并位移场（脸部形变 + 颈肩协调） → 单次 warp
  → 变换关键点（同一 MLS 映射）
  → 美妆：使用变形后的关键点定位
  → 输出：编码保存，保留 EXIF 与颜色配置；Debug 由 AutoBeauty 写入 processed/，Release / iOS 由用户导出
```

### 3.2 对外 API（草案）

```swift
let engine = try BeautyEngine()
let analysis = try await engine.analyze(image)              // 检测与蒙版，可缓存
let preview  = try await engine.render(analysis, params: params, quality: .preview)
let final    = try await engine.render(analysis, params: params, quality: .full)
```

### 3.3 性能与交互策略

- 检测结果与蒙版按图片缓存，调节参数时不重新检测
- 拖动滑杆时使用 1024 像素的预览代理图，松手或导出时使用 4096 工作图
- 形变只重算 MLS 与位移场，属于小规模 CPU 计算

### 3.4 局部修饰（M4）

蒙版在皮肤蒙版分辨率（预览 256 / 全分辨率 512）上生成，渲染时按双线性采样放大，因此边缘天然柔和。

| 区域 | 定位方式 | 判据 | 渲染 |
|---|---|---|---|
| 眼白 | 眼轮廓多边形（76 点） | 绝对亮度 + 「相对眼内中位亮度」取较大者，并要求低饱和 | 提亮并轻微去饱和，虹膜不参与 |
| 牙齿 | 内唇多边形（缺失时退回外唇） | 亮度高、饱和度低、无红偏 | 提亮 + 轻微提升蓝通道（中和偏黄） |
| 眼下 | 眼睛下缘外推的椭圆 | 皮肤蒙版内、亮度低于全脸平均 | 加性提亮 + 轻微微暖中和，避免橙色条带 |
| 痘印 | 皮肤蒙版（无需额外通道） | 低频底色与原始像素的亮度差 | 按比例抬升像素自身亮度，并向邻域色度收敛 |

眼白使用「绝对 + 相对」双判据的原因：实测暗光、眯眼、小尺寸素材中眼内最高亮度只有 0.35~0.55，纯绝对阈值会完全失效；而纯相对判据在眼白占据多边形大部分时会自我抵消。闭眼时眼内亮度分布平坦，两个判据都不成立，蒙版自然为空。

去痘印的参考亮度取自原图的低频模糊（不取已磨皮 / 已美白的像素），因此美白、提亮不会抵消瑕疵检测；修复采用增益方式抬升像素自身纹理，而不是替换成模糊值。

### 3.5 皮肤蒙版判据

肤色判定有两种模式，按是否检测到人脸切换：

| 模式 | 触发条件 | 判据 |
|---|---|---|
| 相对（首选） | 检测到人脸 | 从人脸框内采样肤色参考，按「亮度归一化色度距离」判定 |
| 绝对（兜底） | 无人脸 / 采样不足 | 固定 YCbCr 阈值带 + 亮度与饱和度下限 |

相对判据的核心是把色度按亮度归一化：`((Cb - 0.5) / luma, (Cr - 0.5) / luma)`。漫反射光照下 RGB 同比缩放，Cb/Cr 与 luma 同比变化，因此该比值对阴影与高光不敏感，只在肤色真正改变时才移动。

这样做的原因是绝对阈值无法区分「暖白色衣物」与「偏暖肤色」——实测一张室内自拍里，面部肤色 Cb/Cr 为 (0.41, 0.65)、白 T 恤为 (0.43, 0.57)，两者都落在传统肤色带内，饱和度 0.36 与 0.22 也没有清晰分界。改用相对判据后，衣物到肤色参考的归一化色度距离为 0.19，而同一张脸上的肤色像素集中在 0.01~0.03，可以稳定区分。

参考值取人脸框内缩 12%、排除眼/唇/眉之后所有像素的中位数，对头发丝、鼻孔、痣等离群点稳健；单张人脸采样不足 40 像素时退回绝对判据。

判定阈值随 `tolerance` 缩放：内半径 `0.05 + 0.02 × tolerance`，外半径 `0.09 + 0.04 × tolerance`，两者之间用 smoothstep 平滑过渡。

在该照片上的实测效果：白 T 恤亮度变化从 +9.74 降到 +0.11（变化像素 99.9% → 1.35%，领口缝线纹理保留），脸部仍为 +7.00、脖子 +8.44，背景严格 0；皮肤蒙版覆盖率 61.2% → 25.8%。

已知限制：混合肤色的合影共用同一参考；强单色光会让参考整体偏移；鼻梁镜面高光与面部绒毛被白光稀释后落在蒙版外，在磨皮强度拉满时会凸显为亮丝（默认档位不可见）。

### 3.6 磨皮：亮度引导的保边滤波

磨皮不使用高斯模糊，而是**以原图亮度为引导图的保边滤波**（guided filter）。对每个像素在局部窗口内拟合线性模型 `q = a·I + b`，`I` 为引导图（原图亮度），`a`、`b` 由窗口内的均值与协方差解出：

- **平坦的皮肤区域**：局部方差远小于正则项 `eps`，`a → 0`，输出趋近窗口均值，毛孔与细纹被抹平；
- **强边缘**（眉毛、睫毛、发丝、眼白与眼睑交界、唇线）：局部方差远大于 `eps`，`a → 1`，输出趋近原图，边缘完整保留。

因此强度拉满时皮肤被磨平，而五官轮廓与毛发不变淡、不变形——不会出现高斯磨皮那种「整张脸一起糊掉」的结果。

| 参数 | 取值 |
|---|---|
| 窗口半径 | `max(1, scale × (3 + 9 × smoothing))`，`scale = max(1, 长边 / 1024)` |
| 正则项 eps | `0.010 + 0.040 × smoothing`；半平滑点落在亮度标准差 ≈ √eps 处 |
| 混合权重 | `0.85 × smoothing × 皮肤蒙版` |

实现采用 Fast Guided Filter：统计量与线性系数在 1/4 分辨率上计算（4×4 方框降采样 + 两次 `MPSImageBox`），再按全分辨率双线性放大后回代。开销约为全分辨率的 1/16，实测在 2316×3088 样图上与不做磨皮相比没有可测差异，并省掉了原先那张全分辨率高斯纹理。

去痘印的低频参考仍然用高斯：那里要的是「把瑕疵平均掉」的大尺度均值，保边反而会把瑕疵本身留下来。

### 3.7 脸型形变（M5）

脸型（小脸 / 瘦脸 / 窄脸 / V 脸 / 下巴 / 额头 / 颧骨）用 **MLS 形变**（Schaefer et al. 2006，纯 Swift 实现于 BFAlgorithms，无平台依赖）：

- **求解**：逆向映射 `f(v)` 输出「输出像素 → 源图采样位置」。控制点上精确成立（`f(p_i) = q_i`），远离控制点时按 `1/(d²+ε)` 权重衰减回恒等。
- **控制点**：76 点轮廓按纵坐标分带位移（下颌、V 脸、下巴、额头、颧骨各占不同区段），单点位移上限为脸高的 10%、超出线性压缩（R-02）；图像边框加恒等锚点。
- **位移场**：多张脸的控制点合入一次 MLS，在长边 128 节点的粗网格上预计算位移。网格节点显式乘距离衰减——`0.15×R` 以内不衰减、`0.45×R` 以外**严格为 0**（R 为脸半径），保证背景零形变；发丝随脸小幅移动属设计内的混合带。
- **折叠防护（R-02）**：对位移场做中心差分雅可比，行列式 ≤ 0（重采样会撕裂）即按 0.7 整体回退强度重解。实测全参数拉满最小雅可比 0.042 > 0。
- **渲染**：位移场上传为 `rgba16Float` 纹理，Metal kernel 双线性采样位移后对源图双线性重采样——**整图只重采样一次**（ADR-006）；位移可忽略时直接返回原图。
- **顺序**：颜色与平滑之后、编码之前做 warp（ADR-007）；位移场同时供后续美妆阶段变换关键点，保证形变与美妆不错位。

| 参数 | 取值 |
|---|---|
| 网格 | 长边 128 节点，多脸合入一次求解 |
| 位移上限 | 脸高的 10%，超出线性压缩 |
| 距离衰减 | smoothstep(0.45R, 0.15R, 到最近关键点的距离) |
| 折叠回退 | ×0.7 重解，最多 12 次 |

实测（`IMG_0789.HEIC`）：全参数拉满最大位移 122px、无折叠、背景与衣服逐像素不变；warp 自身开销 < 0.3s。

## 六、构建与运行

**环境要求**

- Xcode 26 或更新版本
- macOS 15 或更新版本，Apple Silicon 芯片（日常开发与调试在此运行）
- iPhone 17 或 iPhone Air 真机（最终验收；Mac 上的性能与内存数据不作为验收依据，见 ADR-013 / ADR-014）

**运行步骤**

1. 打开 `BeautyFace.xcworkspace`
2. 选择 `BeautyFaceDemo` Scheme，目标设备选择 My Mac 或 iOS 设备
3. Debug 配置使用本机签名（`CODE_SIGN_IDENTITY = "-"`），无需开发者证书；Release 与真机运行仍需有效的 Apple Development 证书
4. `BeautyFaceDemo` 始终使用 PhotosPicker；系统相册路径只在非 Debug 模式下验证
5. iPhone 真机验证推迟到核心功能基本完成后；首次运行需在设备上信任开发者证书

**快速调试（AutoBeauty，仅 macOS）**

核心功能开发阶段使用 `AutoBeauty` 直接读取 `SampleImages/`，无需相册交互与人工点击：

```bash
swift run --package-path Tools/AutoBeauty AutoBeauty
```

- 默认批量处理 `SampleImages/` 下的全部图片
- 结果写入仓库根目录 `processed/`（已加入 `.gitignore`）
- 支持 `--input <目录>` / `--output <目录>` 覆盖默认路径
- M1 起已接入 BFKit：解码、EXIF 方向归一、4096 长边缩放、rgba16Float 工作纹理与编码输出
- M2 起默认检测人脸与人像蒙版，并输出 `_debug.png`（人脸框、76 点关键点、半透明蒙版）
- M3 起默认输出美化结果，并输出 `_skin.png`（皮肤蒙版灰度图）
- M4 起同时输出 `_retouch.png`（局部修饰蒙版叠加：青=眼白、黄=牙齿、品红=眼下），终端打印各区域像素数与峰值
- 参数：`--quality preview|full`、`--smooth <0...1>`、`--white <0...1>`、`--bright <0...1>`
- 局部修饰参数：`--eye`（亮眼）、`--teeth`（白牙）、`--dark-circle`（去黑眼圈）、`--blemish`（去痘印）
- 示例：`swift run --package-path Tools/AutoBeauty AutoBeauty --quality preview --smooth 0.5 --white 0.3 --bright 0.2`
- 只验证局部修饰：`swift run --package-path Tools/AutoBeauty AutoBeauty --smooth 0 --white 0 --bright 0 --eye 1 --teeth 1 --dark-circle 1 --blemish 1`
- `--no-detect` 关闭检测与美化，`--no-mask` 跳过人像蒙版（仅肤色）；需指定可执行名

**算法层单独测试**（不需要真机）

## 七、测试

- **算法层**：`swift test` 在 Mac 上运行，覆盖 MLS 求解、参数映射、预设编解码、衰减函数。
- **AutoBeauty**：批量处理 `SampleImages/`，输出到 `processed/` 做回归与前后对比。
- **恒等回归**：合成测试图经 `rgba16Float` 工作纹理往返，最大通道误差 ≤ 1 灰阶。
- **人脸检测**：样例图检测 1 张脸、拼接图检测 2 张脸；76 点关键点；人像蒙版非空。
- **皮肤处理**：肤色 + 人像蒙版生成皮肤蒙版，眼/唇多边形排除；恒等参数往返误差 ≤ 1 灰阶。
- **皮肤蒙版判据**：暖白色衣物（Cb/Cr 落在传统肤色带内）不应算作皮肤；同一肤色压暗 40% 后仍应被识别，用于验证亮度归一化对阴影不敏感。
- **局部修饰**：合成人像（眼白/虹膜/牙齿/唇/眼下暗沉）验证蒙版几何——眼白覆盖巩膜且不含虹膜，牙齿不含唇，眼下落在眼睛下方，背景与额头为 0。
- **痘印修复**：合成暗斑经去痘印后亮度回升，无瑕疵区域不变；开启美白后相对修复量不被抵消。
- **局部渲染隔离**：亮眼 / 白牙 / 去黑眼圈各自只改变对应蒙版内像素，蒙版外 ≤ 1 灰阶。
- **快照测试**：固定图片与参数，输出与参考图比较，允许少量容差。
- **背景保护**：蒙版外像素变化接近 0（实测 ≤ 1 灰阶）。
- **几何检查**：位移场雅可比行列式为正，防止折叠；极端位移触发强度回退后仍为正。
- **MLS 求解器**：恒等控制点返回原值、控制点上精确命中、远场衰减回恒等、多脸互不干扰。
- **脸型参数**：7 项参数各自只朝预期方向移动对应的轮廓带，其余带不受影响；位移超上限被线性压缩。
- **Warp 渲染**：零位移返回原图；恒等误差 ≤ 1 灰阶；强形变下背景与衣服不变。
- **真机验收**：两台设备 × 三类素材（前置自拍、4800 万像素原图、多人合影）。

详细的验收标准与测量方法见 `dev_ledger.md` 的里程碑章节。
